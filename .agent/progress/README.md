# progress — 开发进度账本

> 让**任意会话**都能在数秒内回答「开发到哪一步了、下一步做什么」。AI 编码助手每次开发任务的前-中-后都围绕这里的三份记录运转；人类协作者也可随时翻看。详见 [development-progress 技能](../skills/development-progress/SKILL.md)。

## 目录结构

```
progress/
├── README.md      # 本文件：账本约定
├── STATUS.md      # 权威状态快照：阶段 / 当前任务 / 下一步 / 挂起 ——「三秒定位我在哪」
├── TODO.md        # 待办清册：按里程碑分块，前-中-后实时维护
├── ROUNDS.md      # 追加式轮次账本：每轮做了什么 / 验证结果 / 遗留
└── history/       # 轮次归档（ROUNDS 过长时，把旧段迁进来）
```

## 三份记录的分工与写入时机

| 文件 | 回答的问题 | 谁在什么时候写 |
| --- | --- | --- |
| `STATUS.md` | 现在在哪、下一步最该做什么 | 每轮**收尾**更新一次；阶段切换时重写 |
| `TODO.md` | 有哪些待办、每块做到哪了 | 开发**中**每完成一小步同步；收尾勾/补 |
| `ROUNDS.md` | 一路走来每轮做了什么 | 每轮**收尾**追加一条（追加式，不改历史） |

## 铁律（保持轻量，别让它长胖）

1. **唯一事实来源**：当前进度以 `STATUS.md` 为准；`TODO.md`/`ROUNDS.md` 只做它的补充证据。改一处时同步另外两处，绝不保留第二份「新鲜副本」。
2. **小而可扫读**：每份文件控制在单页内能扫完。超过 → 归档旧段到 `history/`，正文只留当前。
3. **只记能续上会话的最小事实**：一条 3-5 句即可。不记过程流水账、不复制代码、不贴命令输出。
4. **追踪可迁移**：状态/待办/轮次都必须带可定位的指针（文件路径、`tdds/` 编号、`KI-xx` 编号），让下一个会话点得穿。

## 记录规范

- `TODO.md` 状态图例：`[ ]` 待办 · `[~]` 做中 · `[x]` 完成 · `[!]` 阻塞（行尾写原因与恢复条件）。
- `ROUNDS.md` 追加式：每轮一条 `## <日期> 第 N 轮`，含 目标 / 本轮做了什么 / 验证 / 遗留。
